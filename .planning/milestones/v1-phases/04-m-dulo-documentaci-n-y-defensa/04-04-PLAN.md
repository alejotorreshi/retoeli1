## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator shell → pre-flight | the access code enters through the environment |
| pre-flight → public service | the script is an authenticated client of the production API |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-10 | Information disclosure | access code in argv, logs or report | high | mitigate | Code only from PREFLIGHT_ACCESS_CODE via env.ts; parseArgs has no code option; tests assert no printed line contains the code |
| T-04-11 | Denial of service | self-lockout of the defense IP | high | mitigate | One config request; 401 and 429 are final with no retry (test counts requests); never sends any other code |
| T-04-12 | Tampering | malformed health, config, file list or SSE frames | medium | mitigate | zod schemas with satisfies on every parsed payload; any parse failure fails the step |
| T-04-13 | Denial of service (cost) | tokens spent by a routine warm-up | medium | mitigate | Default mode never POSTs /api/chat (test with a counting fetch); --guion is explicit and opens one session |
