<objective>
Close the two warnings of 02-REVIEW.md that the verifier also reproduced.

WR-02 (fix the code, user decision). evaluarEnvio marks the grant used before the tool runs, and despacharEnvio emits an event only for an ok send. When an authorized proveedor_simular_envio fails (PAQUETE_DESACTUALIZADO, PAQUETE_NO_ARMADO, ERROR_INTERNO), or the turn then closes by error or tope, and no fresh successful armado follows in that turn, the case silently leaves the gate. That contradicts D-63.2 and the knowledge (registro-proveedor.md:53-54 "el servidor vuelve a pedir la confirmación"). Fix: a failed authorized send emits a new gate event, FALLIDO, which the fold treats exactly like a blocked attempt. The case returns to pending with its known package, and the server asks again, in any turn ending except a caller abort. The used grant is never restored (D-38). Recorded as D-63.7.

WR-01. The 02-17 fix only looks at the end of the composed text. With two or more config issues, each TEXTO_ENV message ends with a period and formatearIssues joins them with "; ", so the startup message carries a period right before the separator. Fix the join: every issue except the last drops its trailing FIN_DE_ORACION, so the message ends with exactly one period. Pin it for a custom provider without URL nor model, and for both URLs on http.

Purpose: make ENV-02 and ENV-03 hold after a failed confirmed send (the analyst always sees the question again and nothing is lost or sent twice), and re-close AGT-05 for the multi-issue configuration path of LLM-02.
Output: EVENTO_COMPUERTA.FALLIDO end to end with loop tests for every failure path; the corrected issue formatter with a unit table and the exact multi-issue literals; the knowledge line for a failed send; D-63.7 and STATE records.
