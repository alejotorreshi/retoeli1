Root cause (binding, from 02-REVIEW.md CR-05 and the gap reason in 02-VERIFICATION.md). Three D-63.9 mechanisms:
1. colasDeComplemento accepts only cases, NEGACIONES and RELLENO after a generic verb or a modal. The server's own wording ("simulado", "confirmación") and reason connectors ("porque", "hasta") are not accepted, and since ":" no longer cuts, a reason after ":" becomes complement.
2. esPalabraDeEspera excludes every case token, and esRechazoExplicito drops the wait clause when another affirmed clause names any case, pending or not.
3. "detén" is a rejection core but not a cancellation, so "detén el envío" fits no form.

The rule changes:
- (a) Complement tail. A send complement is also a COMPLEMENTOS_DE_ENVIO word ("simulado", "confirmacion"). The tail is cut, so whatever follows is the reason and does not count, at a CORTES_DE_COMPLEMENTO word ("porque", "hasta", "pues", "sin", "mientras") or at the first token after a ":" inside the clause. ":" still does not cut clauses, so "el cliente respondió: no." stays otro. Cancellation ("cancela…", "detén…") uses the same tail.
- (b) Vocabulary. CANCELACIONES gains "deten" and "detente". RELLENO_DE_ESPERA gains "hoy".
- (c) Pending case in a wait clause.
  - Inside a wait clause, a pending case counts as a wait word. When the clause names a pending case, the RELLENO fillers ("el", "paquete", "de"…) count too.
  - Contrast rule: a negator that does not follow another wait word, followed by a case or a filler, is a contrast and never forms a wait clause. So "procesa co-industrias-delta, no ec-corp-andina", "dame el NIT, no la de ec-corp-andina" and "No ec-corp-andina, ¿qué falta?" stay otro.
  - The whole-message wait also admits the pending case and its fillers, but then needs a rejection core: "no ec-corp-andina" rejects, "mejor co-industrias-delta" does not.
- (d) Exemption (user decision "Acotar la regla", 2026-10-14). Another affirmed clause exempts the wait clause when it names a case that is not pending, or when it is led by a request verb (VERBOS_DE_PEDIDO: "procesa", "consulta", "lee", "revisa", "dame", "dime", "muéstrame"…) and names any case. So no request that names a case cancels a pending case: "No, consulta el NIT de co-industrias-delta" stays otro with both cases pending. A statement about the pending case ("Todavía no, falta el certificado de ec-corp-andina", "no, el de ec-corp-andina tiene bloqueos") does not exempt.

Three user-approved pairs. "No, el de ec-corp-andina" has no request verb and the same shape as "no, el de ec-corp-andina tiene bloqueos", which must reject. So three message-pendientes pairs of the generated never-cancel corpus now reject:
- "No, el de ec-corp-andina" with one pending case and with two;
- "No, el de co-industrias-delta" with two pending cases.

The user approved these three flips in this session on 2026-10-14, so the plan stays autonomous with no checkpoint. The corpus is not edited.
