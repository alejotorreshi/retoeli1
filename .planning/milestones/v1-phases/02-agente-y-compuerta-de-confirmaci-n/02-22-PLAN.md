<objective>
Close gap G-02-2 of 02-UAT.md (UAT round 2, test 2, severity major, diagnosed in .planning/debug/g-02-2-negaciones-amplias.md).

Root cause (binding): clasificarConfirmacion (src/domain/policies/confirmacion.policy.ts:82-89) has no scoped notion of an explicit rejection. Line 84 returns otro for any message with "?" or "¿" before negations are looked at, and line 86 returns rechaza when ANY word of the message is in NEGACIONES (src/config/constants/confirmation.constants.ts:63-89), a list that mixes real stop words with ordinary connectors ("para", "luego", "después", "mejor", "momento", "aún", "ni", "nada"). The rule dates from 02-03 (RESEARCH Pattern 7), when otro and rechaza had the same effect (D-37). D-63.6 made rechaza cancel every pending case and otro keep it with the server question, but never redefined a rejection (02-19-PLAN.md:405). So "Consulta el valor del NIT de co-industrias-delta para tenerlo a mano" cancels the pending case silently (the model says it is still pending, and the next "sí" is blocked with CONFIRMACION_REQUERIDA: a double confirmation, the CR-01 symptom), and "No envíes nada todavía, ¿qué falta?" keeps the case pending and the server asks to confirm right after the analyst said not to send. Swapping the two checks alone is wrong: 7 of 8 ordinary questions would become rejections. Both parts change together.

User decision (QA round 2, HV2): "no-pass → plan de cierre: acotar NEGACIONES y que la negación gane a la pregunta, con pruebas de bucle ('…para tenerlo a mano', 'No envíes nada todavía, ¿qué falta?')". WR-17 (the button rejection of one case cancels all) is explicitly out of this plan. HV1 (A2 model variance) was accepted: no prompt change for it and no live run.

The new definition, recorded as D-63.8 (planner wording of the user's direction, verified on a scratch prototype: 1207 pass, 0 fail, tsc and Biome clean). A message is an explicit rejection only if:
- (a) a negator ("no", "nunca", "jamás", "tampoco", "ni") governs a send form: it is followed, with at most unstressed pronouns in between, by "envíes", "envíe", "envíen", "mandes", "mande", "manden", "despaches", "despache", "despachen", "hagas", "confirmo" or "autorizo". This counts anywhere in the message, even when it also asks a question; or
- (b) one of its clauses is not a question and is made only of NEGACIONES words and RELLENO fillers, with at least one NEGACIONES word ("no", "todavía no", "aún no, espera", "mejor no", "cancela el envío", the "No" of "No, ¿qué falta?").
The rejection check runs before the question check. Any other message that merely contains one of those words, inside another request or a question, is otro: the case stays pending and the server asks again (D-63.6). The rule only moves messages between rechaza and otro. The confirmation grammar already refuses every NEGACIONES and NEGADORES word, so the set of phrases that confirm does not change.

Purpose: make the D-63.6 promise hold for real phrasing. An unrelated request keeps the case pending with one server question, an explicit "no envíes" cancels even with a trailing question, and the prompt and the knowledge describe the same rule the server applies (ENV-02, ENV-03, AGT-02, DEMO-03).
Output: the scoped classifier with its constants and clause pattern, unit rows and invariants, loop tests through the agent with the scripted fetch for both user scripts and their siblings, the aligned prompt and knowledge with contract pins that run the classifier on the quoted examples, D-63.8 in 02-CONTEXT.md and the corrected STATE.md line.
</objective>
