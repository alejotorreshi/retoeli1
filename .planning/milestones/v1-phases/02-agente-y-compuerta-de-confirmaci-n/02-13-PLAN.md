<objective>
Close code review WR-02, in scope by user decision, and re-run the live check after all five gap fixes.

WR-02: a confirmation turn ("envía") that fails before the send happens drops the pending case without telling the analyst. That happens on a provider error after retries and fallback, the token budget, missing instructions or the deadline. If the analyst retries "envía", it is classified against an empty pending set and blocked. The behavior chosen here follows the locked decisions. D-63.2 says the pending state and the question also apply when a turn ends in an error or a cap and the package is armed, so the authorized case goes back to pending and the turn ends with the server question. D-38 says the grant itself is consumed at turn end, so the analyst must confirm again. Recovery is not offered on a final ending (the model chose not to send) or on a caller abort.

Purpose: re-close ENV-02, ENV-03 and AGT-04 (CA5 for the confirmation step), with DEMO-03 coverage. Then produce the fresh live evidence that 02-VERIFICATION.md asks for, now that CR-02 (plan 02-10) and CR-01 (plan 02-14) have changed the behavior the 02-09 live run had tested.
Output: recuperarAutorizado, its use in the turn closing, unit and loop tests, and a VIVO PASS line with a human check of the replies.
</objective>
