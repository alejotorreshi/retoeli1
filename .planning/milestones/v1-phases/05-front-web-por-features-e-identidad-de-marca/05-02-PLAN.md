<objective>
Build the front's own store (D-101) and move every pure reducer next to its feature (D-120), without wiring the store into the UI yet. The core is about forty lines with no dependency; the actions absorb `usar-chat.ts` and `usar-salud.ts` with the network injected, so they are tested without a DOM; the selectors are memoized so `useSyncExternalStore` never loops (FE-02). The architecture guardian learns the new homes of pure state and the new folders (FE-04).

Purpose: FE-02 asks for a predictable state in a store of our own built with `useSyncExternalStore`, Context and selectors, over the existing pure reducers. Proving the store and its actions in isolation first makes plan 05-03's wiring a swap, not a rewrite.
Output: `web/src/store/*`, `web/src/types/store.type.ts`, the reducers under `web/src/features/*/estado/`, two new slices, store tests, and W4/W13 updated with negative samples.

This plan runs in parallel with 05-01 (disjoint files). It does not touch the DOM tests; it does not mount anything.
</objective>
