<objective>
Give the server a structured, per-case answer to its confirmation question (D-68, D-69): POST /api/chat accepts `accion { tipo, caso }`, the gate honors it only for a case pending in the session, confirmar authorizes exactly that case, and cancelar removes only that case. This fixes the Phase 2 limitation where the structured rejection cancelled every pending case (WR-17) while keeping every gate guarantee.

Purpose: UI-03 and CA3 with the server as the only gate; plan 03-23 builds the cards on this contract.
Output: TIPO_ACCION, the CANCELA_CASO decision, `EntradaTurno.accion` (replacing the old structured confirmation), accion through the API body, and the updated gate tests.
</objective>
