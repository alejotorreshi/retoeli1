| Client-chosen session id → session store | A guessed or replayed id |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-28 | Information disclosure | Session view leaking reasoning, system prompt, PII or secrets | high | mitigate | vistaDeSesion skips system messages and the model's reasoning, exposes only ok/codigo/resumen/resultado per call and redacts with the three secrets; sesiones.test.ts scans for maestro values and sentinels |
| T-03-29 | Spoofing / Information disclosure | Guessing or replaying a session id | medium | mitigate | Ids are random UUIDs checked by PATRON_SESION, every read needs access (cookie or Bearer), leer never creates or renews a session, and the 404 reveals nothing beyond "expired" |
| T-03-SC | Tampering | npm installs | high | mitigate | No new package in this plan; exact pins, bun.lock and bun audit in bun run check |
</threat_model>
