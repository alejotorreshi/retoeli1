Research proposed the remaining details (A2, A4-A8, A11), and they need a human yes before code depends on them.

    Option A is the full proposal (research "Tool Contract Spec"):
    - Success is `{ ok: true, data, resumen }`. Failure is `{ ok: false, error, codigo, parcial?, resumen }`. `error` is a Spanish catalog message and `codigo` is an UPPER_CASE stable code. `resumen` is an additive Spanish summary built only from counts and codes.
    - `parcial` is the single optional structured carrier. It holds `casos_disponibles` (D-14), `etiquetas_esperadas` (D-15), `diferencias` (D-11) and `{ pais, cliente, formato, soportes }` (D-17).
    - Every path in `data` is relative to ctx.directory, for example `out/<caso>/formulario.xlsx`.
    - The `caso` arg is `z.string().max(64)`. Inside the tools, `""` gives CASO_NO_ENCONTRADO plus `casos_disponibles`. Failing `^[a-z0-9-]{1,64}$` or escaping the casos dir after realpath gives CASO_INVALIDO. A missing folder gives CASO_NO_ENCONTRADO plus `casos_disponibles`.
    - `leer_solicitud` data is `{ caso, pais, cliente, formato, plantilla, campos: {etiqueta, obligatorio: boolean|null}[], ambiguos: {etiqueta, estado:"requiere_confirmacion", propuesta}[], soportes: string[] }`.
    - `mapear_campos` takes args `{ caso, campos: string[] }` (at most 200; `[]` means all template labels, and any subset is matched with glossary normalization per D-15). Its data is `{ caso, pais, conteo:{lleno,faltante,requiere_confirmacion}, llenos[], faltantes[], requiere_confirmacion[], mapeo:"out/<caso>/mapeo.json" }`. Each item is `{ etiqueta, ruta: string|null, estado, regla, confianza, valor_enmascarado: string|null, nota: string|null, propuesta: string|null }`. The default mask literal is `[dato oculto]`.
    - `generar_formulario` takes args `{ caso, mapeo: {etiqueta, estado, ruta: string|null}[] }`, with each item `.strict()` and `ruta` matching `^[a-z_]+(\.[a-z_]+)*$`. For xlsx and pdf, data is `{ ruta, formato }`. For portal it is ok:true with `{ ruta:"out/<caso>/valores-portal.md", formato:"portal", aviso:"formato no soportado" }`. A mismatch with the canonical recompute gives MAPEO_INCONSISTENTE plus `parcial.diferencias`, which names canonical etiquetas only and refers to unknown items as `#<index>`.
    - `armar_paquete` takes `{ caso }` and returns `{ ruta:"out/<caso>/paquete", listo_para_firma, bloqueos: string[], checklist:{ fecha_ejecucion, soportes:{tipo, estado:"presente"|"ausente"|"vencido", vigencia_hasta, archivo|null, aviso|null, aviso_emisor|null}[], faltantes: string[], requiere_confirmacion:{etiqueta, nota}[] }, archivos: string[] }`. Expired soportes are still copied into paquete/.
    - `simular_envio` takes `{ caso, confirmado: z.boolean().default(false) }`, so a missing confirmado counts as "sin confirmación" (ENV-01, ROADMAP SC4) rather than ARGS_INVALIDOS. It returns `{ ruta:"out/<caso>/ENVIO-SIMULADO.md", bloqueos: string[] }`. The check order is args, then caso, then `confirmado !== true` giving CONFIRMACION_REQUERIDA with the literal "requiere confirmación explícita", then a missing paquete giving PAQUETE_NO_ARMADO, then the write.
    - Template selection (SOLI-01): only plantilla-celdas.json with xlsx gives xlsx. Only plantilla-campos.json with pdf gives pdf. Either file with portal gives portal. Only plantilla-campos.json with xlsx gives PLANTILLA_INVALIDA. Only plantilla-celdas.json with pdf gives a pdf built from its labels in order. Both files or neither gives PLANTILLA_INVALIDA.
    - `out/<caso>/mapeo.json` is value-free: `{ caso, pais, fecha_ejecucion, campos: [same item shape as mapear_campos] }`.
    - Two codes are added beyond the D-18 minimum: CONFIGURACION_INVALIDA and DATOS_INVALIDOS.
