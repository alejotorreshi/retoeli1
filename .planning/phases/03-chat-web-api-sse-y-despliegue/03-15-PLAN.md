<objective>
Close the last cost gap of D-73: creating sessions must not reset the 300 k per-session cap, so new sessions are limited to five per hour per client IP, and an invented sessionId counts as new (Pitfall 8). This needs a read-only session lookup that neither creates nor renews a session, which plan 03-20 also uses for the session view.

Purpose: with this plan every D-73 layer has a configurable default, a clear Spanish refusal and a test that proves it cuts, and no request path can reach the LLM around them.
Output: `AlmacenSesiones.leer`, `Agente.existeSesion`, the new-session limit in the chat route, and the closing tests of tests/http/topes.test.ts.
</objective>
