<objective>
Close the API behind a shared access code, following D-72: the analyst sends the code once, the server answers with an HttpOnly signed cookie that lasts 12 hours, and every protected endpoint checks it (curl can use Bearer).

Purpose: this must exist before the first public deploy (plan 03-11), because an open /api/chat on a public link would let anyone spend the prepaid LLM balance. The brute-force limit (03-06), the config endpoint and agent-side redaction (03-08), the input edge (03-09) and the access screen (03-10) build on this tracer.
Output: the access route, the access middleware, the token service, the access env vars, the shared test helper sending Bearer by default, and tests that prove each check cuts.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → /api/acceso | Anyone can try codes |
| Browser cookie jar → /api/* | Cookie value is client-held and can be forged or replayed |
| Server secrets → responses and logs | The access code and the HMAC secret live in the process |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-10 | Spoofing / Elevation | Forged or expired access cookie | high | mitigate | HMAC-SHA256 signature via setSignedCookie/getSignedCookie, expiry inside the signed value checked on the server, separate ACCESS_TOKEN_SECRET required in production |
| T-03-36 | Information disclosure | Access code and HMAC secret in responses, SSE frames or http logs | high | mitigate | The http wiring adds both to the redaction secrets of toSseFrame and of the http logger; acceso.test.ts asserts CODIGO_PRUEBA and SECRETO_PRUEBA appear in no body, header or frame; the cookie carries only the version and expiry |
| T-03-SC | Tampering | npm installs | high | mitigate | No new package in this plan; existing exact pins, bun.lock and bun audit in bun run check |
</threat_model>
