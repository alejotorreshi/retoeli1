<objective>
Give the front a behavior safety net before anything moves. This plan installs the test-only devDependencies the user approved (D-115), wires a per-file happy-dom setup that never touches the backend tests, and writes characterization tests that mount the real `App` with only the network faked at `fetch`. Because those tests talk to the App the way the server does, the same assertions keep passing through every later plan of the refactor (FE-06, D-116). It also widens the code guardians to `.tsx` tests so the new test files obey the same rules (FE-04).

Purpose: FE-06 forbids behavior change. A black-box suite at the network boundary is the strongest automated proof that the refactor in plans 05-02 to 05-07 changes structure only.
Output: pinned devDeps with SOLUCION.md §6 rows, `tsconfig.dom.json` and the third `tsc` in `check`, the DOM/network/app helpers, four characterization files, a backend sentinel, and `.tsx`-aware guardians.

The run is unattended (D-104). The supply-chain check is automated and fail-closed: the user named the packages in D-115, the SUS flag from the research applies only to the newest releases, and the plan pins older versions and verifies them before installing. Browser QA stays in eli-qa (D-117).
</objective>
